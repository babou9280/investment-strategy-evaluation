# Breaktest Cost Intelligence — confidentialité minimale du test

## Objet

Définir la frontière de données du premier test utilisateur. Ce document prépare une éventuelle publication ; il ne remplace pas une politique juridique complète ni un conseil professionnel.

## 1. Principe de minimisation

Le premier calculateur doit fonctionner sans transmettre :

- capital ;
- montant des ordres ;
- fréquence ;
- hypothèses de coûts ;
- résultat du calcul ;
- identité ;
- compte courtier ;
- historique de transactions.

Ces valeurs restent dans le navigateur tant qu'aucun service externe n'est explicitement activé.

## 2. Données interdites pendant la première vague

Ne jamais demander ni conserver :

- identifiant ou mot de passe de courtier ;
- numéro de compte ;
- clé API ;
- document d'identité ;
- relevé non anonymisé ;
- adresse postale ;
- patrimoine détaillé ;
- objectif d'investissement personnalisé ;
- tolérance au risque ;
- numéro de carte bancaire.

Si un participant les saisit ou les envoie spontanément, demander leur suppression et ne pas les recopier dans les notes.

## 3. Partage du résultat

Par défaut, le résumé partagé peut contenir :

- type d'activité ;
- taille de l'ordre ;
- fréquence ;
- hypothèses de coût ;
- résultats agrégés ;
- version de la formule.

Le capital exact reste exclu sauf choix explicite. Email, pseudonyme et réponses au questionnaire sont toujours exclus.

Le texte doit rappeler qu'il s'agit d'hypothèses saisies et non d'une observation vérifiée.

## 4. Test utilisateur modéré

Les notes peuvent contenir :

- tranche de capital ;
- tranche de fréquence ;
- difficultés rencontrées ;
- verbatims utiles ;
- intention ou comportement observé.

Éviter de noter le nom complet. Utiliser un identifiant de participant, par exemple `P01`.

Aucun enregistrement audio ou vidéo sans consentement distinct, finalité claire et durée de conservation définie.

## 5. Email futur

Le formulaire email reste techniquement désactivé jusqu'à décision explicite.

Avant activation, il faudra au minimum :

- identifier le responsable du traitement ;
- préciser la finalité unique ;
- afficher un consentement non précoché lorsque requis ;
- prévoir désinscription et suppression ;
- choisir un prestataire et vérifier ses conditions ;
- documenter les champs transmis ;
- définir une durée de conservation ;
- ne jamais joindre les données financières du calcul à l'email sans consentement distinct.

## 6. Analytics futurs

Le premier test peut être réalisé sans analytics tiers.

Avant toute activation :

- vérifier si une mesure locale ou agrégée suffit ;
- limiter les événements aux étapes produit nécessaires ;
- ne pas transmettre les valeurs financières saisies ;
- ne pas enregistrer le texte partagé ;
- éviter fingerprinting et reciblage publicitaire ;
- documenter les cookies ou technologies équivalentes ;
- obtenir le consentement lorsque nécessaire.

Événements conceptuels utiles, sans données financières :

- ouverture du calculateur ;
- calcul valide ;
- erreur de formulaire ;
- ouverture de la méthode ;
- interaction avec la comparaison ;
- clic de partage ;
- demande d'information future.

## 7. Paiement futur

Aucun paiement n'est actif.

Avant activation :

- utiliser un prestataire spécialisé ;
- ne jamais traiter les données de carte dans le code Breaktest ;
- afficher prix, objet, remboursement et absence d'abonnement automatique ;
- séparer paiement et consentement marketing ;
- fournir une confirmation ;
- vérifier les obligations de consommation et de facturation applicables.

## 8. Conservation et suppression

Pour les notes de test manuelles :

- conserver uniquement les informations nécessaires à la décision produit ;
- supprimer les coordonnées lorsque le suivi est terminé ou demandé ;
- séparer les coordonnées des observations ;
- ne pas publier un verbatim identifiable sans autorisation ;
- documenter toute suppression demandée.

## 9. Incidents

En cas d'envoi ou d'exposition inattendue de données :

1. désactiver le canal concerné ;
2. conserver les faits techniques nécessaires à l'analyse sans propager les données ;
3. identifier la nature, le volume et les destinataires ;
4. supprimer les copies inutiles ;
5. demander un avis juridique si la situation le justifie ;
6. corriger le défaut et ajouter un test de non-régression ;
7. ne pas minimiser l'incident dans la communication.

## 10. Limite

Ce document est un garde-fou produit. Avant collecte publique, import de relevés, connexion courtier, profil utilisateur ou commercialisation à grande échelle, une revue juridique et sécurité adaptée sera nécessaire.
